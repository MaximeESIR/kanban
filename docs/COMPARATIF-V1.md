# Comparatif V1.0 / flyingpafnouti/kan

Référence : code au commit `563ea3864e1fb0dd0ffcb80f1cf4337633af1fe2`. Comparaison de capacités implémentées, pas un audit indépendant de sécurité ni un benchmark des modèles. Les capacités connectées d’Atelier attendent les comptes et moteurs décrits dans CONNEXION-PC.md.

| Point différent                                     | Référence                                                          | Atelier V1.0                                                                                             | Pourquoi                                                                | Avantage et limite                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Traitement IA                                       | Groq, clé API dans les métadonnées du compte accessibles au client | Service PC, Ollama/faster-whisper ; aucun fournisseur IA requis                                          | Choix explicite sans clé API IA                                         | Atelier pour indépendance et contrôle ; référence plus simple sans PC allumé                    |
| Disponibilité du PC                                 | Pas de service PC dans le dépôt                                    | Présence, capacités, demandes, états, annulation, expiration                                             | Traitements depuis le téléphone ou le PC avec la même interface         | Atelier pour ce besoin ; branchement et qualité à tester sur le vrai matériel                   |
| Réécriture                                          | Remplacement puis Undo                                             | Aperçu avant application, annulation, refus d’écraser une note modifiée pendant le calcul                | Préserver les modifications concurrentes                                | Atelier sur protection du brouillon ; référence possède un prompt partagé persistant            |
| Recherche                                           | Recherche textuelle approchée                                      | Recherche textuelle + classement de sources par LLM local                                                | Retrouver une fonctionnalité avec ses propres mots                      | Atelier pour le sens avec PC disponible ; recherche approchée également disponible sans IA      |
| Hors ligne                                          | Cache et file de mutations                                         | IndexedDB, verrou inter-onglets, reçus idempotents, contrôle de révision et archive des conflits         | Éviter les pertes silencieuses entre appareils                          | Atelier pour les conflits ; copies de conflit récupérables en notes, puis fusion manuelle       |
| Synchronisation                                     | Realtime + reprises                                                | Actualisation toutes les 3 secondes, aucune recharge manuelle                                            | Transport simple testable, pas de publication Realtime à configurer     | Référence pour latence et trafic ; Atelier conserve une latence bornée en usage normal          |
| MFA                                                 | Activée compte par compte, fraîcheur TOTP de 90 jours dans le code | TOTP obligatoire et AAL2 imposé par RLS pour tous les comptes humains                                    | Application personnelle reliée à un ordinateur                          | Atelier sur obligation ; aucun service ne protège une session volée ou un appareil déverrouillé |
| Images                                              | Bucket privé, liens et redimensionnement                           | Images recompressées intégrées aux notes, pas de chargement d’images distantes                           | Pas de stockage supplémentaire, usage hors ligne/export simple          | Atelier pour portabilité ; référence pour volume et redimensionnement interactif                |
| Formules                                            | MathJax                                                            | KaTeX                                                                                                    | Rendu local, bundle plus léger                                          | Dépend des formules ; MathJax couvre davantage de TeX                                           |
| Installation mobile                                 | PWA                                                                | PWA, cache statique, mise à jour sans interruption de saisie                                             | Une seule application web/mobile                                        | Comparable pour installation ; tests physiques iOS/Android restent à faire                      |
| Gestes et clavier                                   | Appui long pour réordonner, nombreux raccourcis                    | Défilement tactile, appui long sur poignée, boutons de tri, navigation clavier et raccourcis /, n, Échap | Conserver une interaction accessible                                    | Atelier offre aussi le tri par boutons ; référence garde davantage de raccourcis avancés        |
| Structure des tickets                               | Priorités                                                          | Priorités, difficulté, dépendances et rejet des cycles                                                   | Besoin initial                                                          | Atelier pour planifier les dépendances                                                          |
| Note vers ticket                                    | Conversion                                                         | Copie explicite, original conservé                                                                       | Éviter les pertes ; pièces volumineuses restent dans la note            | Atelier pour conservation ; description du ticket limitée à 12 000 caractères                   |
| Pro/Perso, vue globale, thème sombre, archives Done | Présents                                                           | Présents                                                                                                 | Retrouver le confort de la référence                                    | Capacités comparables, interfaces différentes                                                   |
| Partage multi-utilisateur                           | Invitations, membres avec droits identiques                        | Espace strictement personnel                                                                             | Périmètre personnel demandé ; aucun accès implicite au PC pour un tiers | Référence pour le travail partagé ; Atelier réduit les droits au besoin personnel               |
| Agents de développement                             | Aucun worker d’exécution trouvé dans le dépôt examiné              | Architecture et séparation des permissions documentées ; aucun exécuteur actif                           | Cette étape a été réservée pour plus tard                               | Aucun des deux n’exécute les tickets à ce stade                                                 |
| Validation automatisée                              | Aucun script de test dans le package examiné                       | Tests PostgreSQL/RLS, IndexedDB, worker, navigateur et PWA hors ligne                                    | Exigence utilisateur                                                    | Atelier pour la couverture vérifiable ; ne remplace pas les essais Supabase/moteur réels        |

La V1 ne peut donc pas être décrite honnêtement comme supérieure sur tous les points. Elle ajoute le lien PC et des protections de synchronisation, mais le dépôt de référence conserve des avantages d’ergonomie et de partage explicitement listés ci-dessus.

## Mise à jour du 1er novembre — Atelier V1.1

Le tableau précédent garde la photographie du 31 octobre. La nouvelle référence examinée est le commit [`c5c77f9`](https://github.com/flyingpafnouti/kan/commit/c5c77f9d43f6f530dcef2822034c8cb529388ae3), après trois nouveaux commits.

| Ajout de la référence                                                                  | Atelier V1.1                                                                                                                             | Différence et intérêt                                                                                                                                                |
| -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Parent qui attend ses tickets enfants ; indentation et compteur de blocages            | Parent de regroupement distinct de jusqu’à 50 prérequis par ticket ; indentation, compteurs, navigation et notification de disponibilité | Atelier autorise qu’un même prérequis débloque plusieurs fonctionnalités. Le parent ne bloque pas implicitement : il faut choisir les prérequis.                     |
| Contrôle des candidats dans l’interface et protection de l’affichage contre les cycles | Contrôles de cycles et d’appartenance au projet/propriétaire dans l’interface et dans PostgreSQL                                         | Atelier protège aussi les écritures directes et les synchronisations différées ; tests SQL et IndexedDB ajoutés.                                                     |
| Tri global priorité / modification récente                                             | Même choix, conservé sur l’appareil                                                                                                      | Fonction similaire ; notre vue globale reste une liste, celle de la référence est un tableau.                                                                        |
| Enregistrement d’un ticket à la fermeture, navigation et mise en arrière-plan          | Enregistrement à la fermeture/en arrière-plan, plus brouillons locaux persistants et garde contre les révisions obsolètes                | Atelier permet de reprendre une saisie interrompue ou de créer une copie en cas de conflit. Les brouillons non enregistrés ne sont pas synchronisés entre appareils. |
| Pas de nouvel exécuteur de développement dans ces trois commits                        | Service local texte/audio/recherche, toujours sans exécuteur de code                                                                     | Aucun des deux projets examinés ne propose encore une équipe d’agents qui développe les tickets automatiquement.                                                     |

L’intérêt d’Atelier reste son adaptation au PC personnel et ses contrôles de synchronisation. La référence aurait aussi constitué une base raisonnable à reprendre ; cette comparaison ne prétend pas établir une supériorité globale d’ergonomie ou de fiabilité en production.

## 9 novembre 2026 — outils MCP et confort des tickets

Référence examinée : [`1390f85`](https://github.com/flyingpafnouti/kan/commit/1390f858417d128792de5c157790aa5648f4d243), notamment son serveur [`mcp/src/index.ts`](https://github.com/flyingpafnouti/kan/blob/1390f858417d128792de5c157790aa5648f4d243/mcp/src/index.ts). Les anciennes lignes « aucun exécuteur identifié » décrivent les révisions précédentes, pas ce nouvel état. L’ajout MCP permet à un client compatible de lire et traiter les tickets ; cela ne remplace pas à lui seul un exécuteur de code, son modèle ou ses permissions sur le PC.

| Point                          | Référence examinée                                                                                    | Adaptation Atelier                                                                                                                                            | Avantage et limite                                                                                                                                                         |
| ------------------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Outils MCP et fin de tâche     | Neuf outils et un prompt `work_next_issue` qui clôture le ticket automatiquement à la fin du parcours | Compte agent dédié, projets explicitement autorisés, mutations avec contrôle de révision ; rapport puis validation humaine dans le navigateur                 | Atelier conserve le choix demandé par le propriétaire : l’agent livre son résultat, l’humain décide de Done. La référence automatise davantage la clôture.                 |
| Historique des descriptions    | Vingt descriptions précédentes remplacées par un agent ; restauration SQL                             | Même périmètre de vingt versions agent, avec aperçu et bouton de restauration dans le ticket ; une révision distante plus récente bloque la restauration      | Atelier facilite la récupération depuis le téléphone. Cet historique ne couvre pas toutes les modifications humaines ni tous les champs.                                   |
| Copier et réutiliser un ticket | Copie Markdown et duplication vers un projet                                                          | Copie Markdown avec état et relations ; duplication en To do, relations conservées dans le même projet et retirées dans un autre, aucune exécution déclenchée | Capacités proches. Atelier préserve les contraintes de projet et crée du travail nouveau, sans recopier rapport ni exécution.                                              |
| Références entre tickets       | Références fondées sur un préfixe d’UUID, affichées avec le titre                                     | `#numéro` cliquable dans le rendu d’une description vers un ticket connu du même projet, titre en infobulle ; code et liens Markdown existants conservés      | Atelier utilise les numéros déjà affichés dans ses cartes. Les références vers d’autres projets ne sont pas résolues automatiquement.                                      |
| Tri du tableau                 | Priorité, récence et ordre manuel                                                                     | Choix mémorisé par projet et appareil ; le tri d’affichage ne modifie pas les positions manuelles ; hiérarchie parent/enfants conservée                       | Capacité comparable. Le réordonnancement dans une colonne est disponible en mode manuel ; le déplacement entre colonnes reste possible.                                    |
| Instructions de réécriture     | Prompt persistant dans les métadonnées du compte, dictable                                            | Prompt commun aux notes et tickets, conservé localement par compte jusqu’à déconnexion                                                                        | Atelier évite un stockage serveur supplémentaire. La référence est plus complète pour le partage entre appareils et la dictée du prompt.                                   |
| Images dans les descriptions   | Stockage privé et gestion d’images plus complète                                                      | Insertion ou collage d’une petite image PNG/JPEG/WebP, recompressée localement ; refus si texte et image dépassent ensemble 12 000 caractères                 | La référence convient mieux aux tickets riches en images. Atelier conserve son format portable et ses limites existantes ; les images volumineuses restent dans les notes. |

Le dessin interactif et un stockage de grosses pièces jointes ne sont pas ajoutés dans cette livraison. Les améliorations de copie, de tri et de saisie fonctionnent en démonstration ; les fonctions MCP, historique et validation demandent la migration 009 et un compte agent autorisé. Les tests du navigateur simulent les réponses Supabase : une activation sur le compte réel reste nécessaire pour valider le parcours complet avec un client MCP.
